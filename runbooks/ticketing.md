# Ticketing workflow

1. Log every request as a ticket, even when it is fixed on the spot.
2. Categorise it (incident or service request) and set priority by impact and urgency.
3. Acknowledge the user and give a realistic time.
4. Work the ticket and record each step in plain language.
5. Escalate with the steps already tried, so the next tier does not repeat them.
6. Confirm with the user before closing, and note the fix for the knowledge base.

Local lab: see [ticketing/README.md](../ticketing/README.md) for categories, priority matrix, SLAs, escalation and an SLA report script.
